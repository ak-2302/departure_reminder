# 出発リマインダー React + Capacitorアプリ仕様書

## 参考

- Google Calendar API `events.list`
- Google Calendar API 認証スコープ
- Google Maps Platform Routes API
- Android Developers 通知・正確なアラーム
- Androidアプリ開発の指針、GUIユーザインタフェースの指針、Webサイトやアプリのデザイン指針

## 1. 概要

Googleカレンダーの予定を取得し、予定の場所までの移動時間をGoogle Maps Platformで算出する。予定に間に合う出発時刻を計算し、ユーザーが必要な時だけ確認できる控えめなバイブレーションで知らせるReact + Capacitorアプリである。

アプリの目的は、予定の管理や経路案内そのものではなく、「いつ家を出ればよいか」をユーザーが考えなくても済むようにすることである。

## 2. 想定ユーザーと利用場面

- Googleカレンダーを日常的に使うユーザー
- 自宅から職場、学校、予約場所などへ移動するユーザー
- 音声や大きな通知を避けたいユーザー
- 出発前にスマートフォンを常に見ているとは限らないユーザー

初期版では、自宅または出発地点を1か所登録し、予定ごとの目的地へ向かう用途を対象とする。実装はReactをWeb UI、Capacitorをモバイルブリッジとして使用する。

## 3. 対象範囲

### 3.1 初期版で実装する範囲

- Googleアカウントによるログイン
- Googleカレンダーの読み取り
- 予定の場所の取得
- 出発地点の登録
- 移動手段の選択
- Google Maps Routes APIによる所要時間の取得
- 余裕時間を加えた出発時刻の算出
- 出発時刻のバイブレーション通知
- 予定、経路、通知状態の確認
- 通信失敗、場所なし、権限拒否などのエラー表示

### 3.2 初期版では実装しない範囲

- Googleカレンダーへの予定の作成・変更・削除
- アプリ内でのターンバイターンナビゲーション
- 複数地点を経由する旅程の最適化
- 家族や他ユーザーとの予定共有
- ユーザーの常時位置追跡
- 交通機関の遅延を保証した到着時刻の算出

## 4. 用語と計算定義

| 用語 | 定義 |
| --- | --- |
| 予定開始時刻 | Googleカレンダーの時間指定予定の開始時刻 |
| 目的地 | 予定の `location` を住所または地名として解決した地点 |
| 移動時間 | Routes APIが返す出発地点から目的地までの所要時間 |
| 準備時間 | 出発前に身支度・戸締まりなどに使う固定時間 |
| 余裕時間 | 遅延や乗換え失敗に備えて加える時間 |
| 出発時刻 | 予定開始時刻 − 移動時間 − 準備時間 − 余裕時間 |
| 通知時刻 | 出発時刻に通知の振動遅延補正を加味した時刻 |

基本式：

`出発時刻 = 予定開始時刻 - 移動時間 - 準備時間 - 余裕時間`

初期値は準備時間15分、余裕時間10分とする。どちらも設定画面で変更可能にする。

## 5. 機能仕様

### 5.1 初回設定

1. アプリの目的と、Googleカレンダーを読み取る理由を表示する。
2. Googleアカウント認証を開始する。
3. `calendar.events.readonly` を基本スコープとして要求する。
4. 出発地点を入力する。
5. 移動手段を選択する。
6. 準備時間、余裕時間、通知タイミング、振動パターンを設定する。
7. Capacitorのネイティブ通知権限が必要な場合は、用途を説明してから要求する。

### 5.2 カレンダー予定の取得

- 対象は現在時刻以降、設定した先読み期間内の予定とする。初期値は7日間。
- 繰り返し予定は個別の発生予定として取得する。
- 終日予定は初期版では出発通知の対象外とし、「終日予定のため計算対象外」と表示する。
- キャンセル済み予定は対象外とする。
- `location` が空の予定は対象外とし、一覧には理由を表示する。
- 複数カレンダーを取得する場合は、初回設定で対象カレンダーを選択可能にする。
- 更新時は差分同期を利用し、同期トークンが無効になった場合は全件再同期する。

### 5.3 目的地の解決

- カレンダーの場所文字列をそのままRoutes APIへ渡す。
- 解決結果が曖昧な場合は、候補を表示してユーザーに選択させる。
- 住所が解決できない場合、通知を自動作成せず、予定詳細に「場所を確認してください」と表示する。
- 目的地は予定単位でキャッシュし、場所文字列が変更されたら再解決する。

### 5.4 移動時間の取得

移動手段は以下を提供する。

- 徒歩
- 自転車
- 自動車
- 公共交通機関

自動車では交通状況を考慮した経路を優先する。公共交通機関では予定開始時刻への到着を基準に経路を取得し、乗換え・徒歩区間を含む所要時間を用いる。

経路取得は以下のタイミングで行う。

- 新しい対象予定を取得したとき
- 予定詳細を開いたとき
- 通知予定の24時間前
- 通知予定の60分前
- ユーザーが手動更新したとき

取得した移動時間には取得日時を保存する。古い経路しかない場合は、その日時を表示し、通知文にも「経路情報は○時時点」と示す。

### 5.5 出発時刻の計算

- 予定開始時刻、経路所要時間、準備時間、余裕時間から計算する。
- 予定開始時刻が現在時刻より前の場合は、通知を作成しない。
- 出発時刻が現在時刻から5分以内の場合は、即時に「出発時刻です」と通知する。
- 移動時間を取得できない場合は、通知を作成せず、失敗理由を表示する。
- 予定が更新された場合、既存の通知を取り消して再計算する。
- 予定が削除・キャンセルされた場合、対応する通知を取り消す。

### 5.6 バイブレーション通知

通知は音を鳴らさず、振動を基本とする。Capacitorの通知・Haptics連携で音なし・振動ありを設定し、ユーザーが端末設定から変更できるようにする。

初期パターン：

| 状態 | 振動パターン | 通知内容 |
| --- | --- | --- |
| 出発30分前 | 短い振動2回 | 「30分後に出発」 |
| 出発時刻 | 中程度の振動3回 | 「出発時刻です」 |
| 出発後かつ予定前 | 長い振動1回＋短い振動2回 | 「予定に遅れる可能性があります」 |

初期版では、同じ予定について最大3回まで通知する。通知をタップすると予定詳細を開く。通知から「今回は無視」「この予定は通知しない」を選択できる。

通知が端末設定で無効、振動が無効、省電力制限中などの場合は、アプリ内に状態を表示する。バイブレーションだけに依存せず、通知欄にも同じ情報を表示する。

### 5.7 予定一覧

起動時の主要画面は、近い予定を出発時刻順に表示する。

各項目に表示する情報：

- 予定名
- 予定開始日時
- 目的地
- 移動手段
- 移動時間
- 出発時刻
- 通知状態
- 経路情報の取得日時

重要な予定を最上部に大きく表示し、装飾的なカードや常時動くアニメーションは使用しない。

### 5.8 設定

- Googleアカウントの接続状態
- 対象カレンダー
- 出発地点
- 移動手段
- 準備時間
- 余裕時間
- 先読み期間
- 通知タイミング
- 振動パターン
- 通知の有効・無効
- データ削除とGoogleアカウント連携解除

連携解除では、アプリが保持するアクセストークン、予定キャッシュ、経路キャッシュ、対応する通知を削除する。Google側の認可自体の取消しは、Googleアカウントのセキュリティ設定から行う。

## 6. 画面仕様

### 6.1 ホーム画面

目的は「次に出るべき時刻」を一目で伝えることである。

- 最上部：次の出発時刻と残り時間
- 中段：予定名、開始時刻、目的地
- 下段：移動時間、準備時間、余裕時間の内訳
- 操作：予定詳細、手動更新、設定
- 空状態：対象予定がないことと、次回同期時刻を表示

### 6.2 予定詳細画面

- 予定の元データ
- 目的地の解決状態
- 経路取得日時
- 移動時間と経路の概要
- 算出された出発時刻
- 通知予定一覧
- 「この予定を通知しない」操作
- Google Mapsで経路を開く操作

### 6.3 初回設定・権限画面

権限要求をまとめて表示せず、カレンダー、通知、必要時の位置情報の順に、目的を説明して要求する。位置情報は常時取得せず、現在地を出発地点に設定する機能を追加する場合だけ要求する。

## 7. システム構成

### 7.1 技術前提

- React + TypeScript + Vite
- Capacitor
- Capacitor Preferencesによるローカル設定保存
- Capacitor Hapticsによる振動フィードバック
- Reactの状態管理とRepositoryによる責務分離
- CapacitorプラグインまたはWeb APIによる通知・バックグラウンド処理
- Google Identity ServicesによるOAuth 2.0
- Google Calendar API
- Google Maps Platform Routes API

APIキー、OAuthクライアント情報、アクセストークンはソースコードやログに直書きしない。Routes APIのキーはリリース環境で制限し、必要に応じてバックエンド経由にする。

### 7.2 主要コンポーネント

```text
  React UI
    └─ React state / hooks
        ├─ CalendarRepository ─ Google Calendar API
        ├─ RouteRepository ─ Routes API
        ├─ DepartureCalculator
        ├─ NotificationScheduler ─ Capacitor plugin
        └─ LocalDataStore ─ Capacitor Preferences
```

### 7.3 ローカルデータ

保存するデータ：

- Googleアカウント識別子（表示用の最小情報）
- カレンダー識別子と選択状態
- 予定ID、発生予定ID、最終更新時刻
- 予定名、開始・終了時刻、場所文字列
- 解決済み目的地の座標または参照情報
- 経路の移動手段、所要時間、取得日時
- 出発地点、ユーザー設定、通知状態

予定の説明文、参加者情報など、出発計算に不要なデータは保存しない。ログには住所、予定名、アクセストークンを出力しない。

## 8. 権限とプライバシー

- Googleカレンダー：読み取り専用スコープのみ。
- 通知：Android 13以降では通知権限を要求する。
- 正確な時刻の通知が必要な場合は、対象AndroidバージョンとGoogle Playポリシーを確認したうえで、正確なアラーム権限の採用可否を決定する。
- 位置情報：初期版の必須権限にしない。出発地点は住所入力を基本とする。
- 予定情報と場所は個人情報として扱い、端末内で暗号化またはOSの安全な保存領域を利用する。
- Google連携解除時は、アクセストークン、予定キャッシュ、経路キャッシュ、通知を削除する。
- プライバシーポリシーに、取得項目、利用目的、保存期間、削除方法、Googleへの送信項目を明記する。

## 9. エラー・例外仕様

| 状況 | 動作 |
| --- | --- |
| Google認証失敗 | 再試行と設定画面への導線を表示。既存キャッシュは直ちに削除しない |
| カレンダーAPI通信失敗 | 最終取得データを表示し、古さを明示。再試行を制限 |
| Routes API通信失敗 | 経路取得日時を保持し、通知を保留。手動再試行を提供 |
| APIのレート制限 | 指数バックオフで最大3回まで再試行 |
| 予定の場所が空 | 対象外として表示し、通知を作成しない |
| 目的地が曖昧 | ユーザー選択を要求し、未選択なら通知を作成しない |
| 予定が過去 | 通知を作成しない |
| 通知権限拒否 | ホーム画面に警告を表示し、設定への導線を提供 |
| 端末再起動 | 保存済みの未来の通知を再構築 |
| 時刻・タイムゾーン変更 | 予定と通知を再同期し、再計算 |
| オフライン | 利用可能なキャッシュを表示し、未取得の経路は「計算不可」と表示 |

## 10. 非機能要件

- 通常起動からホーム画面表示まで3秒以内を目標とする。
- 通信はUIスレッド外で実行する。
- 同一予定への重複通知を防ぐ。
- バッテリー消費を抑えるため、常時位置追跡と短周期ポーリングを行わない。
- TalkBack、文字サイズ拡大、ダークテーマ、画面回転に対応する。
- 予定数が多い場合も一覧を遅延読み込みし、UI操作をブロックしない。

## 12. 受け入れ条件

- Googleアカウント連携後、対象期間の予定を表示できる。
- 場所のある予定について、設定した出発地点からの移動時間を取得できる。
- 予定開始時刻、移動時間、準備時間、余裕時間から出発時刻を正しく算出できる。
- 予定変更時に、古い通知を取り消して新しい通知を登録できる。
- 指定時刻に音なしのバイブレーション通知を行い、通知欄にも内容を表示できる。
- 場所なし、通信失敗、認証失敗、権限拒否をユーザーが理解できる形で表示できる。
- 端末再起動後も未来の通知を復元できる。
- 予定情報、認証情報、位置情報を必要以上に保存・送信しない。

## 13. 未確定事項と初期仮定

- 初期版の対象地域は日本とする。公共交通の提供範囲と時刻精度は地域に依存する。
- 「家」は住所入力で登録し、現在地の自動取得は後続機能とする。
- 余裕時間の初期値は10分、準備時間の初期値は15分とする。
- バイブレーションのみでは気づけない場合があるため、通知欄表示を必須の補助情報とする。
- Google Mapsの利用料金、APIキー管理、利用規約、Google Playの権限ポリシーは実装・公開前に再確認する。
